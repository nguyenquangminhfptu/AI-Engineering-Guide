Top-down ≠ bỏ nền tảng

Không học 1 tháng toán trước. Mỗi khi gặp khái niệm (softmax, cross-entropy, LoRA rank…) trong task thật, dừng lại học đúng phần đó cho đến khi tự giải thích được.

"Train LLM" ở công ty = Fine-tuning

Pretraining from scratch cần hàng nghìn GPU — chỉ cần làm nanoGPT để hiểu. Fine-tuning open model (Qwen, Llama) bằng dataset riêng mới là việc hằng ngày của AI Engineer.

03 / PORTFOLIO

4 dự án chứng minh năng lực

PROJECT 01 · AGENTIC · TUẦN 1–2

Claude Skill + MCP Server cho team

Một skill và một MCP server giải quyết workflow lặp lại ở công ty, đo bằng eval set trước/sau khi cải tiến.

Deliverables: SKILL.md, MCP server, eval set 20+ case, điểm baseline → cải tiến.

PROJECT 02 · MODEL ENGINEERING · TUẦN 3–4

nanoGPT from Scratch

Tự viết tokenizer, causal self-attention, decoder blocks, training loop, sampling.

Deliverables: model code, training curves, generated samples, ghi chú giải thích hyperparameters.

PROJECT 03 · FINE-TUNING · TUẦN 5–7

Domain LLM: base → SFT → DPO

Dataset từ task công ty, fine-tune open model 1–8B bằng LoRA/QLoRA rồi DPO, so sánh trên held-out eval set cố định.

Deliverables: dataset card, LoRA adapters, bảng benchmark, error analysis.

PROJECT 04 · CAPSTONE · TUẦN 8–12

End-to-end AI System

Dataset → fine-tuned model → agent/skill dùng model đó (+ RAG nếu cần) → eval harness trong CI → deploy bằng vLLM + Docker.

Deliverables: repo public, architecture diagram, eval dashboard, write-up.

05 / STUDY SYSTEM

Quy tắc học để tiến bộ thật

Phân bổ ~12 giờ mỗi tuần (ngoài giờ làm)

  • 2 giờ lý thuyết (video, docs, sách)
  • 6 giờ code và thí nghiệm
  • 2 giờ áp dụng vào task ở công ty
  • 2 giờ eval + viết write-up / README

Definition of Done

  • Giải thích được nguyên lý bằng lời của mình
  • Tự code được, không copy nguyên notebook
  • Có con số eval trước/sau
  • Ghi lại lỗi gặp phải và cách sửa
  • Push code + write-up lên GitHub

Ưu tiên dành cho Software Engineer

Biến mỗi ticket AI ở công ty thành bài tập: làm task, rồi dành một buổi tối học lý thuyết phía sau nó. Tận dụng kỹ năng API, testing, CI/CD — eval chính là test suite cho LLM. Hoãn lại: classical ML/XGBoost, AWS chuyên sâu, pretraining lớn.

Tránh những sai lầm phổ biến

Không nói "cảm thấy tốt hơn" — phải có số; không eval trên dữ liệu training; tách eval set trước khi train; không học framework thay cho bản chất; không chạy agent nguy hiểm thiếu sandbox và phê duyệt. Sau 2–3 kết quả có số liệu, đề xuất với manager chuyển chức danh sang AI Engineer.
